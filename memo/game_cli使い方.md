# game_cli.py 使い方メモ

`backend-core/scripts/game_cli.py` は、ゲームの一連の流れ（エージェント雇用・お題の実行・会議）を、フロントエンドを待たずにターミナルの番号入力だけで確認できる統合CLIです。単発でお題を1つ投げて素早く試したいだけの場合は、引き続き`scripts/chat.py`が使えます。

## 起動方法

```
docker compose up -d db     # DBが起動していなければ
cd backend-core
.venv\Scripts\Activate.ps1  # venv有効化（PowerShellの場合）
python scripts/game_cli.py
```

## 画面構成（部屋を選ぶ → 部屋ごとのメニュー）

まず「どの部屋にいますか？」で部屋を選び、選んだ部屋によってできることが変わります。

```
どの部屋にいますか？
1. 社長室
2. 会議室（使用中）   ← 会議が進行中の場合のみ「（使用中）」が付く
3. 作業室（使用中）   ← 作業が1件以上進行中の場合のみ「（使用中）」が付く
4. メール（未読件数）
0. 終了
```

### 会議・作業はバックグラウンドで進行する（並行処理）

会議・作業はLLM呼び出しに時間がかかるため、開始すると**その場では結果を待たず、すぐにメニューに戻ります**。裏側では会議・作業がバックグラウンドで進行し続け、その間も社長は他の部屋（エージェント作成、お題一覧の確認など）を自由に操作できます。完了・失敗すると「メール」に通知が届きます（`4. メール`の未読件数が増えます）。

進行中は部屋選択メニューの表示にも反映され、「2. 会議室（使用中）」「3. 作業室（使用中）」のように表示されます（会議室は同時に1件までのため使用中かどうかの二値、作業室は複数件並行できるため「1件以上進行中か」を表します）。「使用中」表示は入室を妨げるものではなく、あくまで状態確認用の目印です。

会議中・作業中のエージェントは、その会議・作業が終わるまで**他のお題の会議・作業には選べません**（参加者・担当者の選択肢一覧から自動的に除外されます）。今どのエージェントが稼働中かは、社長室の「お題一覧を見る」で確認できます（「状態: 会議中（担当: ○○）」のように表示されます）。

CLIを終了しようとした時点でまだ進行中の会議・作業がある場合、それを待ってから終了します（進行中のまま強制終了すると、結果が失われるため）。

### お題の流れ（全体像）

お題は作成時に「会議室での話し合いが必要か」を決め、以下のように状態が進みます。

```
[会議が必要な場合]
お題を作成する（会議待ち）
  → 会議室で会議を開始する（会議中・バックグラウンドで進行）
  → 完了するとメールに通知（レポート承認待ち）
  → 社長室でレポートを承認する（作業可能）
  → 社長室で作業を割り当てる（作業中・バックグラウンドで進行）
  → 完了するとメールに通知（完了）

[会議が不要な場合]
お題を作成する（作業可能）
  → 社長室で作業を割り当てる（作業中・バックグラウンドで進行）
  → 完了するとメールに通知（完了）
```

「作業を割り当てる」では、1つのお題につき**成果物は1件だけ**です。複数の担当者（worker）が役割分担して協力し、リーダーが1つの成果物に統合します（会議と同様、作業にもリーダーを置きます）。

### 1. 社長室

```
1. エージェントを作成する（雇用）
2. お題を作成する
3. 作業を割り当てる
4. レポートを確認して承認する
5. お題一覧を見る
6. お題を編集する
7. お題を削除する
8. 登録エージェント一覧を見る（性格・役職・スキル・AIモデルを確認）
9. エージェントを編集する
10. エージェントを削除する
0. 部屋選択に戻る
```

- **エージェントを作成する**: 名前・性格（一言）・役職・AIモデル・スキル（複数可）を選んで新規エージェントをDBに登録します。
  - 役職に「テクリード」等の上流工程寄りの役職を選ぶと、選べるAIモデルが`capability_tags`に`"design"`を含むもの（現状は`claude-opus-4-8`のみ）に絞り込まれます（ハード制限）。
  - 現状、実際にLLMを呼び出せるのは`deepseek-v4-pro`のみです。それ以外のAIモデル（`claude-opus-4-8`・`claude-haiku-4-5`）を選んでエージェントを作ることはできますが、そのエージェントにお題や会議を依頼すると「このプロバイダはまだ実装されていません」というエラーになります（作成時にも案内が表示されます）。
  - 名前を未入力のまま、または役職・AIモデルの選択で`0`を入力すると、途中でキャンセルできます。
- **お題を作成する**: お題本文を入力し、続けて「会議室での話し合いが必要ですか？(y/N)」に答えます。ここでは担当者の割り当ては行いません（登録するだけです）。
  - `y`（会議必要）: お題は「会議待ち」状態になります。会議室で話し合いを行い、レポートが承認された後に作業を割り当てられます。
  - それ以外（会議不要）: お題は最初から「作業可能」状態になり、すぐに「作業を割り当てる」から進められます。
- **作業を割り当てる**: 「作業可能」状態のお題を選び、担当者（worker）を選びます（**カンマ区切りで複数人選択可**。会議中・作業中のエージェントは選択肢に出ません）。2人以上選んだ場合は、その中からリーダーも選びます（1人だけの場合はその1人がそのままリーダーを兼ねます）。ここで作業は**バックグラウンドで開始**され、すぐにメニューに戻ります（その場では結果を待ちません）。各workerが自分の担当パートを作り、リーダーが1つの成果物に統合します（会議レポートがあれば、その内容も踏まえます）。完了・失敗すると「メール」に通知が届くので、そこで完了を確認してから作業室で内容を見る、という動線になります。
- **レポートを確認して承認する**: 会議が完了し「レポート承認待ち」になっているお題の一覧から選び、「承認しますか？(y/N)」に答えます。**レポートの内容はここでは表示されません。メールの受信箱でのみ確認できます**（会議完了時のメール本文に、会議レポートの全文が含まれています）。承認すると、お題は「作業可能」状態になり、「作業を割り当てる」から進められるようになります。
- **お題一覧を見る**: 社長室で登録済みのお題を、新しい順に一覧表示します。タイトル・`task_id`・会議要否・状態（日本語ラベル）・登録日時が確認できます。「会議中」「作業中」のお題は、担当しているエージェント名も併せて表示されます（例: `状態: 作業中（担当: アレックス、バックエンドエージェント）`）。
- **お題を編集する**: お題を選び、「お題内容」または「会議要否」のうち変更したい項目を選んで更新します。1回の操作で複数の項目を続けて編集でき、「0. 終了」で抜けます。**完了済み（`completed`）のお題は編集できません**。会議要否は、**既に会議が行われた（`meetings`の記録がある）お題では変更できません**（話し合い済みの実績と矛盾する状態にならないようにするため）。会議要否を変更すると、状態も連動して「会議待ち」⇔「作業可能」に切り替わります。
- **お題を削除する**: お題を選び、確認（`y`）すると削除します。**紐づく会議・成果物・メール等の記録も合わせて削除されます**（外部キー制約違反を避けつつ、一括で整合性を保って消すため）。エージェント選択で`0`を入力するとキャンセルできます。
- **登録エージェント一覧を見る**: 現在登録されている全エージェントの、性格・役職・使用AIモデル・スキルをまとめて確認できます。誰にお題や会議を任せるか検討する際の参照用です。
- **エージェントを編集する**: エージェントを選び、名前・性格・役職・AIモデル・スキルのうち変更したい項目を選んで更新します。名前・性格・役職・AIモデルのいずれかを変更すると、システムプロンプト（自己紹介文）も自動的に作り直されます。役職を変更した場合は、その場でAIモデルの選び直しも行います（役職によってはハード制限で選べるモデルが変わるため）。1回の操作で複数の項目を続けて編集でき、「0. 終了」で抜けます。役職・AIモデルの選択で`0`を入力すると、その項目の変更だけキャンセルされ編集メニューに戻ります。
- **エージェントを削除する**: エージェントを選び、確認（`y`）すると削除します。**既にお題や会議で使われたことのあるエージェントは削除できません**（DBの外部キー制約により、関連する成果物・会議の記録が残っているため）。その場合は「削除できませんでした」という案内が表示されます。エージェント選択で`0`を入力するとキャンセルできます。

**キャンセルについて**: 番号を選ぶ場面（役職・AIモデル・エージェント・お題の選択など）では、`0`を入力するといつでもその操作を中止できます（一覧表示の`0`とは別に、選択待ちの入力欄で使えます）。誤ってメニューに入ってしまった場合はこれで抜けられます。

### 2. 会議室

```
1. 会議を開く（リーダー・参加者を選んでエージェント同士で話し合う）
2. 会議が必要なお題一覧を見る
0. 部屋選択に戻る
```

- **議題（お題）は、社長室で「会議が必要」として登録済み・かつ会議未実施のお題からのみ選べます**（会議室でその場に新しいお題を入力することはできません）。先に社長室の「お題を作成する」で、会議室での話し合いが必要なお題として登録しておく必要があります。
- **会議が必要なお題一覧を見る**: 会議未実施（`awaiting_meeting`）のお題を、タイトル・`task_id`・登録日時付きで一覧表示します（「1. 会議を開く」でお題を選ぶ前に、対象を確認したい場合に使います）。
- お題を選んだ後、参加者（2体以上、カンマ区切りで選択。**会議中・作業中のエージェントは選択肢に出ません**）→ リーダー（参加者の中から1名）を選ぶと、会議が**バックグラウンドで開始**され、すぐにメニューに戻ります（その場では結果を待ちません）。各参加者がそれぞれ提案を出し、リーダーがそれらを集約した会議レポートを作成します。完了・失敗すると「メール」に通知が届きます。会議が終わると、お題は「レポート承認待ち」状態になります（作業はまだ始まりません。社長室で承認してください）。
- 会議対象のお題がない場合、または空いているエージェントが2体未満の場合は会議を開けません。先に社長室で「会議必要」なお題・もう1体以上の空いているエージェントを用意してから試してください。
- 同時に進行できる会議は1件までです（会議室は1つしかないという設定のため）。前の会議が完了する前に新しい会議を開こうとするとエラーになります（作業は複数件を並行して進められます）。
- お題・参加者・リーダーいずれの選択でも`0`を入力するとキャンセルできます。

### 3. 作業室

```
1. 作業内容を確認する（実行済みのお題・成果物から選んで内容を見る）
0. 部屋選択に戻る
```

- 社長室で「作業を割り当てる」から実行した結果（成果物、1お題につき1件）が、新しい順に一覧表示されます。番号を選ぶと、実際の内容（担当者の役割分担をリーダーが統合したもの）が表示されます。

### 4. メール

```
1. 受信箱を見る
0. 部屋選択に戻る
```

- 会議・作業が完了・失敗すると、ここに通知が届きます（部屋選択メニューの「メール（件数）」は未読件数）。
- **受信箱を見る**: 通知を新しい順に一覧表示します（未読はそのまま、既読には「（既読）」が付きます）。番号を選ぶと本文を表示し、その場で既読にします。
- **会議完了の通知メールには、会議レポートの全文が本文に含まれます**（社長室の「レポートを確認して承認する」では内容を表示しません。レポート内容の確認はメールでのみ行います）。
- メールへの返信機能はまだありません（完了・失敗を知らせる一方向の通知のみ）。

## データの保存先（DBテーブル）

| 操作 | 保存されるテーブル |
|---|---|
| エージェント作成 | `agents`・`agent_skills` |
| お題を作成する | `tasks`（1件。`requires_meeting`と初期`status`を設定） |
| 会議を開く（予約フェーズ） | `meetings`・`meeting_participants`を作成し`tasks.status`を`meeting_in_progress`に更新（`tasks`は新規作成せず、社長室で登録済みの行を参照する） |
| 会議の完了・失敗（バックグラウンド） | `meeting_proposals`・`meeting_reports`を作成し`meetings.status`・`tasks.status`を更新、`email_threads`・`email_messages`に通知を作成 |
| レポートを確認して承認する | `meeting_reports.approved_at`・`tasks.status`を更新 |
| 作業を割り当てる（予約フェーズ） | `work_sessions`・`work_session_participants`を作成し`tasks.status`を`work_in_progress`に更新 |
| 作業の完了・失敗（バックグラウンド） | `artifacts`（`type="proposal"`。1つのお題につき1件だけ）を作成し`work_sessions.status`・`tasks.status`を更新、`email_threads`・`email_messages`に通知を作成 |
| メールを読む | `email_threads.status`を`closed`に更新 |
| お題を編集・削除する | `tasks`・（削除時は）`meetings`系・`work_sessions`系・`artifacts`・`email_threads`系も合わせて削除 |

`docker compose exec db psql -U postgres -d ai_company` でDBに入り、上記テーブルを直接確認することもできます。
